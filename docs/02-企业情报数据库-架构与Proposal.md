# 企业情报数据库：架构与 Proposal

> 版本：v1.0 · 2026-08-26
> 定位：企业上下游供应商、投资人信息调查的「实时更新数据库」，以 Obsidian 方式组织。
> 前置阅读：《01-obsidian-hermes-collaboration.md》（Obsidian × Hermes 协作机制）。

---

## 0. 目标（一句话）

构建一个**持续更新、可追溯、可视化**的企业情报库，回答三个核心问题：

1. **谁供货** —— 某公司的供应商是谁（supplier）
2. **供什么货** —— 供应商提供什么产品/物料（product）
3. **谁投钱** —— 公司的投资人是谁、投了多少（investor）

系统具备三大能力：**资料搜索能力**、**数据库管理能力**、**关键信息抽取能力**。人能看（图谱/表格），机器能自动更新（定时任务）。

---

## 1. 用户故事（为什么需要）

- **查一家公司**：打开它的笔记 → 供应商列表、客户列表、投资人、创始人、股权结构一目了然。
- **查一个产品**（如"光刻胶"）：谁在生产、谁在采购、替代厂商有哪些。
- **查一个投资人**：投过哪些公司、偏好行业、偏好阶段。
- **产业链视角**：某环节只有一家供应商 → 识别"卡脖子"风险（单一供应商集中度）。

---

## 2. 能力拆解

| 能力 | 具体手段 |
|------|---------|
| 资料搜索 | Hermes 联网搜索 / 浏览器抓取 / 公开 API（工商、招投标、财报）|
| 数据库管理 | Obsidian = 纯文本库（frontmatter 字段 + 图谱 + 查询）；可选 SQLite 镜像做复杂关系查询 |
| 关键信息抽取 | LLM 把非结构化文本（新闻、公告、网页）抽成 (实体, 关系, 属性)，写入结构化笔记 |

---

## 3. 整体架构（数据流）

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌──────────────┐
│ 数据源    │ → │ 采集层   │ → │ 抽取层   │ → │ 存储层   │ → │ 查询/展示层   │
│ 网页/API │   │ cron抓取 │   │ LLM结构化│   │ Obsidian│   │ 图谱/表格/报告 │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └──────────────┘
```

### 3.1 采集层（资料搜索能力）

- **触发方式**：cron 定时（每日/每周）+ 手动指令（"查一下 XX 公司"）+ 网页变更检测
- **抓取手段**：curl / 浏览器自动化 / 官方 API（优先）/ 合规网页抓取
- **输出**：原始文本 + 来源 URL + 抓取时间

### 3.2 抽取层（关键信息抽取能力）

- LLM 接收原始文本，按固定 schema 输出 JSON：
  - 实体：公司、人物、产品、投资人、交易
  - 关系：supplies_to / invested_in / owns / founder_of ...
  - 属性：金额、日期、行业、股权比例
- **反幻觉纪律**：每条抽取结果必须带 `source_url` 和 `fetched_at`；无法确认的信息标注"待核实"。

### 3.3 存储层（数据库管理能力）

**Obsidian vault 就是数据库**，组织方式：

```
Intelligence Vault/
├── 00-总目录.md            ← 索引页
├── 01-公司/                ← Company 节点
│   ├── 苏州XX科技.md
│   └── 深圳YY电子.md
├── 02-人物/                ← Person 节点
├── 03-产品物料/             ← Product 节点
├── 04-投资人/              ← Investor 节点
├── 05-交易事件/             ← Deal / Event 节点（融资、中标、采购）
├── 06-产业链/              ← mermaid 产业链图 + 分析笔记
├── 07-变更日志/             ← 每次更新的记录（可追溯）
└── _模板/                  ← 各类笔记的 frontmatter 模板
```

**节点 = 实体，wikilink = 关系，frontmatter = 属性**，三者构成完整图谱。

可选：SQLite 镜像（幂等同步），用于图算法（路径分析、中心性、集中度）和复杂 SQL 查询。

### 3.4 查询/展示层

| 方式 | 用途 |
|------|------|
| Obsidian 图谱 | 一眼看清供应链/股权网络 |
| Bases / Dataview | frontmatter 字段 → 可排序筛选的表格（如"所有 2024 年后成立的半导体材料公司"）|
| mermaid | 产业链流程图、股权结构图 |
| 报告导出 | 单个公司的尽调简报（markdown → PDF/HTML）|

## 4. 数据模型

### 4.1 实体与关键字段

| 实体 | 关键字段 |
|------|---------|
| Company（公司）| name, credit_code(统一社会信用代码), industry, region, founded, employees, status, website, revenue |
| Person（人物）| name, role(创始人/CEO/董事), title, company |
| Product（产品/物料）| name, category, spec, company |
| Investor（投资人）| name, type(VC/PE/天使/产业资本), fund_size, focus, stage |
| Deal（交易）| type(融资/采购/中标/合作), amount, date, parties |
| Event（事件）| date, type, summary, source_url |

### 4.2 关系（wikilink 语义）

```
A supplies_to B         A 向 B 供货
A purchased_from B      A 从 B 采购
A invested_in B         A 投资 B
A owns B                A 持有 B 股权
A founder_of B          A 创立 B
A board_member_of B     A 是 B 董事
A competitor_of B       A 与 B 竞争
A partner_with B        A 与 B 合作
```

### 4.3 笔记模板示例（Company）

```markdown
---
type: company
name: 苏州XX科技有限公司
credit_code: 91320594MA...
industry: 半导体材料
region: 江苏苏州
founded: 2015
status: 存续
website: https://...
products: "[[晶圆清洗液]]"
suppliers: "[[YY材料]]"
customers: "[[ZZ电子]]"
investors: "[[AA资本]]"
source_url: https://www.qcc.com/...
fetched_at: 2026-08-26
---

# 苏州XX科技有限公司

## 业务
（LLM 生成的 3-5 行摘要，带来源）

## 供应链
- 供应商：[[YY材料]]（供：硅片，来源：2025 年报）
- 客户：[[ZZ电子]]（采购：清洗液，来源：中标公告）

## 股权与融资
- 投资人：[[AA资本]]（A 轮，2024-03，金额未披露）

## 来源记录
- 2026-08-26：初建，来源 URL
```

## 5. 数据源（中文企业尽调）

| 数据源 | 内容 | 方式 | 备注 |
|--------|------|------|------|
| 国家企业信用信息公示系统 | 工商登记、股东、行政处罚 | 官方网页（有验证码）| 权威，自动化受限 |
| 爱企查 / 企查查 / 天眼查 | 工商 + 关系图谱 | 网页 / 付费 API | 反爬严格，建议合规 API |
| 巨潮资讯网 / 上交所 / 深交所 | 上市公司财报、公告 | 公开 PDF/API | **前五大客户/供应商名单** = 供应链金矿 |
| 招投标网站（中国政府采购网、千里马等）| 中标、采购公告 | 网页 | "谁供货"的直接证据 |
| 公司官网 + 招聘页 | 产品线、业务扩张 | 网页 | 招聘 JD 可推断业务和供应链 |
| IT桔子 / 企名片 / 烯牛数据 / Crunchbase | 融资事件、投资人 | 网页 / API | 投资人数据主源 |
| 专利库（国知局 / Google Patents）| 技术布局 | API/网页 | 推断"供什么货"的技术线索 |
| 微信公众号 / 36氪 / 界面新闻 | 公司动态 | 公众号文章、新闻页 | 事件流补充 |

**优先级策略**：上市公司财报 > 招投标公告 > 官方工商 > 商业数据平台 > 新闻。

## 6. 实时更新机制

1. **定时触发**：cron 每日扫描重点公司关键词，每周全量巡检。
2. **变更检测**：监控目标网页 hash，变了才重新抓取（省资源、省 API 费）。
3. **增量更新**：只新增/修改变化的节点，保留 `fetched_at` 时间戳。
4. **去重**：以统一社会信用代码 / 官网域名 / 人物身份证映射 为唯一键。
5. **可追溯**：每次更新写 `07-变更日志/`，记录改动 + 来源；LLM 抽取的内容必须带 URL。

---

## 7. 合规与风险

- 🔴 **只采集公开信息**，遵守目标网站的服务条款，控制抓取频率（防封禁也防法律风险）。
- 🔴 **不采集个人隐私**（手机号、家庭住址等），高管联系方式只保留公开的职务邮箱。
- 🟡 **AI 抽取有幻觉风险**：所有关键信息（金额、股权比例、供货关系）必须有来源 URL 支撑；标注"待核实"。
- 🟡 **商业 API 有成本**：MVP 阶段用公开数据源，验证价值后再上付费 API。
- 🟢 **数据可导出**：纯 markdown + git，随时可迁移、可审计。

## 8. 路线图

| 阶段 | 内容 | 验收标准 |
|------|------|---------|
| Phase 0（约 1 周）| 搭 vault 模板 + 数据模型 + 手工录入 3 家公司 | 图谱里能看清 3 家公司的供应链 |
| Phase 1（2-3 周）| Hermes 采集脚本 + LLM 抽取流水线 + cron 定时 | 新公司输入名称 → 自动生成笔记草稿 |
| Phase 2（1 个月）| 查询面板（Dataview）+ 产业链 mermaid + 尽调简报导出 | 一条指令产出单公司 PDF 简报 |
| Phase 3（持续）| 更多数据源、SQLite 镜像、图分析（集中度/路径/风险提示）| 自动标出"单一供应商依赖"风险 |

---

## 9. 技术栈清单

- **Hermes Agent** —— AI 编排、联网搜索、cron 定时、文件读写
- **Obsidian** —— 图谱 + Bases/Dataview + Templates（全部本地、纯文本）
- **Python** —— 采集与解析脚本（requests / beautifulsoup / pdfplumber）
- **SQLite**（可选）—— 关系查询镜像、去重、图算法
- **LLM API** —— 非结构化 → 结构化抽取

---

## 10. MVP 优先建议

先别追求全自动。**Phase 0 用手工 + Hermes 半自动**跑通三家真实公司：

1. 建好 `_模板/` 和目录结构
2. 让 Hermes 搜索 A 公司的公开信息，生成笔记草稿
3. 人工核对关键关系（供货/投资），修正后入库
4. 打开图谱看效果 → 满意了再上 cron 自动化

这套架构的核心价值不是"全自动"，而是**信息可追溯、关系可可视化、更新可持续**。
